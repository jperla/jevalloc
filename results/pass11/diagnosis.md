# Why defaults retain more RSS — diagnostic only

The placed variants retain mostly reclaimable memory under this quiet defaults protocol. In the forced-collection oracle run, final idle10 RSS is 213.012 MiB; collecting the default heap reduces it to 187.574 MiB, and then collecting the allocating worker’s tagged class heaps reduces it to 41.273 MiB. Workload live bytes do not change. The oracle’s heap areas held only 29.922 MiB of used blocks in 30.075 MiB of committed area before collection. Static-model similarly falls from 215.102 to 43.504 MiB. This supports deferred reclamation, rather than 214 MiB of irreducibly occupied heap pages, as the main cause of the retained placed-variant RSS.

Plain mimalloc is different: defaults RSS changes only from 280.223 to 279.477 MiB. Its live heap areas commit 266.199 MiB for 29.915 MiB of used blocks, with only 0.008 MiB in entirely empty areas before collection. Most of that area capacity is therefore in pages that still contain live blocks. This supports live-page pinning as the dominant baseline heap cost in this workload.

With identical two-cycle and ten-second histories, immediate-purge ordinary idle10 RSS is 280.227 MiB for mi, 41.379 for oracle, and 43.586 for static-model. The separate forced runs change only 280.172→279.480, 41.383→41.141, and 43.582→43.246 MiB. Immediate purge has already returned the placed variants’ reclaimable resident memory by the observation.

All numbers here are individual diagnostic observations from a separate MI_STAT=2 build, not five-run performance medians. Every peak/drop/idle/idle10 phase, both cycles, and every forced-collection observation is in the matrices and the [phase table](results.md). Heap-area traversal can collect delayed frees; every diagnostic policy has the same instrumentation. Forced collection occurs only after the final idle10, preserving both cycle histories through that point.

Counter limitation: mimalloc reports negative signed committed values in the immediate-purge placed variants (for example −5109.301 MiB for the ordinary oracle). These values are preserved but are not valid absolute committed-memory estimates. Even the positive committed/reserved counters include sparsely touched arenas (about 1 GiB reserved here), not just resident memory. Cumulative purged bytes can include repeated purge activity. Do not subtract live bytes from these counters and call the result RSS fragmentation. The conclusion above relies on RSS before/after collection with unchanged workload live bytes, supported by heap-area occupancy. It does not claim every extra resident byte has been individually attributed.

The result describes this allocator version, placement scheme and phase protocol. A passive ten-second wait is not the same operation as servicing deferred reclamation on the affected heaps; it does not show that defaults require a universal timeout longer than ten seconds.
